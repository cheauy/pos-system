## Active behavior with the flag off

- The explicit product Generate action returns a 15-digit internal numeric string derived from 48 random UUID bits, padded with leading zeros. It is not UPC/EAN/GS1 and randomness does not guarantee uniqueness. Empty creation still follows the established SKU fallback; existing uppercase Code39-compatible alphanumeric codes remain accepted.
- Web receipts encode the exact saved 12-digit order_code as Code39. Display order numbers, UUIDs and QR URLs are distinct identifiers and are not substituted. Missing/invalid order_code blocks receipt printing with a saved-sale reload warning; it never retries checkout. Native receipt behavior is unchanged.
- Product labels encode the exact stored barcode or established SKU fallback as Code39, with white quiet zones and explicit roll page dimensions. Existing unsupported codes show an explanation without trimming, letter removal, conversion or replacement. The legacy fixed-label scaling remains; physical readability of every long legacy code is not certified by this release.
- Camera-supported linear scans perform exact current barcode/SKU and order_code/order_number lookup, preserving leading zeros. A single authorized order result opens its details; collisions across visible orders/products show a warning and do not select arbitrarily. Existing QR resolution retains its authorization checks. Ordinary typed search remains a result list; no new USB wedge interception is claimed.
- Lookups use the branch-scoped client, business filters and authorized order loader. A client request carries the expected operating branch. Branch changes and newer scans invalidate stale responses before navigation; old scan intent is not replayed to a new branch.
- No new contract or alias RPC is called while the flag is absent/not 1. Existing schema paths remain. If the flag is enabled but the reviewed contract/alias reads are unavailable, barcode scans, labels and identifier writes fail closed; POS manual product selection and checkout remain available.
